# CONTEXT — Vinayak ProcureAI MVP

## Product
Decision-support application for construction procurement. It ingests requirement email text and Excel BOQs, suggests ERP item codes, drafts an RFQ, extracts quotations, generates an evidence-backed comparative statement, and records a human decision.

## Scope
Six end-to-end stages:
1. Requirement intake: email + Excel BOQ + optional Hindi/Bengali note. Excel quantities are deterministic and never generated by LLM.
2. ERP matching: deterministic lexical candidates from private workbook. AI may explain/re-rank only candidates; it cannot create codes. Human confirms.
3. RFQ: human-confirmed items and six terms read at runtime from the private RFQ sample. If a term is not found, display UNKNOWN.
4. Quotations: PDF/Excel/image upload; extraction includes source evidence. Check quoted quantity × rate against stated amount.
5. Comparison: Python Decimal only. Quantity/unit mismatches require explicit UnitResolution; unresolved lines are excluded from totals. Unknown GST basis/rate => total null.
6. Decision: rule-based shortlist, reasons/evidence, approval note template, human approve/override/reject. Override requires reason.

## Architecture and layer rules
- `api/`: HTTP parsing, request/response models and service calls only.
- `services/`: orchestration and persistence workflow.
- `document/`: PDF/Excel parsing and evidence only; no AI, procurement or services imports.
- `ai/`: Sarvam HTTP provider, gateway, timeout, one repair retry and traces; no procurement/document/services imports.
- `procurement/`: deterministic lexical matching and Decimal comparison only; no AI/document/services imports.
- `schemas/`: standalone Pydantic contracts.
- `database/`: SQLite persistence only.
- `static/`: single-page HTML/CSS/vanilla JS.
- Keep `tests/test_architecture_rules.py` passing.

## AI policy
- Sarvam V2 chat endpoint and documented model IDs only.
- No second provider is configured.
- Text structuring/translation uses Sarvam when key exists.
- Scanned PDF/image OCR uses Sarvam Document AI Parse when key exists; otherwise local Tesseract/Poppler is attempted.
- AI never supplies BOQ quantities, ERP codes, rates, totals or approval decisions.
- Deterministic parsing is the first non-AI fallback. Public fixtures/demo data are synthetic; response caches are stored under gitignored `AI_SAMPLES_DIR` (default `data_private/ai_samples`).
- No live API call is claimed unless tested with the user's key.

## Private data
Extract the uploaded pack into `data_private/vinayak-vch3-data/` (gitignored). Runtime paths:
- ERP workbook: `04_item_codes/ERP_item_codes_waterproofing.xlsx` by default; optional `ERP_CATALOGUE_PATH` overrides it.
- RFQ sample: `03_tender/Sample_RFQ_email_to_a_vendor.txt`
The app reads terms from that private sample at runtime. Never copy terms or source values into code or public fixtures.

## Conventions
- Use Decimal for every financial calculation.
- Missing values stay null/UNKNOWN.
- Every extracted quotation value should carry document/page/line evidence when available.
- Mark assumptions and unknowns explicitly.
- No new dependencies beyond openpyxl, pdfplumber, pytesseract, Pillow and existing stack without asking.
- Review staged files before every commit; no commits/pushes are being made in this local review build.
